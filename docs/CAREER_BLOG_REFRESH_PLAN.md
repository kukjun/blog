# 계획: 커리어 방향에 맞춘 블로그 보강

날짜: 2026-09-13 | 이슈: [#1](https://github.com/kukjun/blog/issues/1) | 브랜치: `docs/1/career-blog-refresh`

## 목표와 배경

한국어 18편과 영어 번역 5편을 읽은 진단을 바탕으로, 사실의 정확성과 작성자의 설계 판단을 강화한다. 대표 주제는 에이전트 실행 경계, 배포 유연성, 서빙 검증이다. 기존 글의 장애 조사 경험은 보존한다.

단일 사실 원천은 커리어 저장소의 최신 `experience/` 기록이다. 이는 과거 실행 기록의 정리이며 이번 작업에서 운영 로그를 다시 측정한 결과가 아니다. 외부 글에는 사내 식별자와 새로운 내부 수치를 옮기지 않는다. 기존 공개 수치는 정의와 근거를 확인해 유지하거나, 확인할 수 없으면 삭제 또는 한정한다. 설명용으로 새로 작성한 코드는 운영 코드나 당시 구현으로 표현하지 않는다.

## 선택지 비교

| 선택지 | 장점 | 비용과 위험 | 판단 |
| --- | --- | --- | --- |
| 전체 글 개작 또는 삭제 | 모든 글의 형식 통일 | 기존 경험과 주소 손실, 과도한 범위, 없는 결과를 채울 유혹 | 기각 |
| 오류만 정정 | 적은 수정으로 신뢰도 회복 | 최근 런타임 역량과 대표글 노출 공백이 그대로 남음 | 부분 채택 |
| 오류 정정 + 대표 3편 보강 + 새 경험 1편 + 대표 목록 | 사실과 커리어 정체성을 함께 강화 | 번역과 화면 확인 필요, 나머지 글의 깊은 개작은 후속 | 채택 |

## 추천 근거와 승인

대표글은 결과를 크게 주장하는 대신 관찰, 가설, 선택, 검증 범위를 연결한다. 동료가 작은 예제를 실행하거나 문서의 수치를 대조할 수 있어야 한다. 기술 동작은 공식 문서와 대조하고, 제품의 현재 기능을 과거 환경에 소급하지 않는다.

사용자는 앞선 진단과 이 작업 순서에 대해 “응 그러면 계획세워서 작업 진행해봐”라고 승인했다. 의도와 결과에 대한 승인이 이미 있으므로 같은 방향의 재승인을 요구하지 않는다. 공개 배포와 main 병합은 이번 승인에 포함하지 않는다.

## 작업 분해

### T1. 근거 기록과 공통 사실 정정

- 기존 `src/content/blog/ko/*.md` 18편, 대응 `en/*.md` 5편에서 앞선 진단이 발견한 모순과 과도한 단정을 수정한다. 대표글 외에는 해당 문단만 수정한다.
- 우선 지점: `ollama-to-vllm.md:11,152`, `vllm-kv-cache-admission.md:3,40,80`, `nfs-open-amplification.md:57,83`, `langgraph-pregel.md:157,183`, `session-aware-routing.md:35,64`, `redis-distributed-lock.md:37`, `s3-pvc-to-efs.md:115`, `cannot-prove-unused.md:74`, `the-number-that-never-existed.md:23`, `ollama-exposed-57-days.md:65`.
- 알려진 근거: 90/21과 472.5/98.6은 별개 지표, 검토 9개/직접 시험 5개/채택 0, NFS 이론치와 실측치 구분. 최신 경력 자료와 기존 글의 차이는 결과 문서에 남긴다.
- 수정한 글에는 `updatedDate: 2026-09-13`을 넣고 원래 `pubDate`와 slug, translationKey를 유지한다.
- 검증: 수정 diff, 수치 산술, 기술 설명의 공식 출처, 한영 짝 대조. 알 수 없는 과거 결과는 만들지 않는다.

### T2. 기존 대표글 3편 보강

- `src/content/blog/ko/k8s-to-single-box.md`: 구성 요소를 제거해도 남는 운영 책임, 인증서 조치, 한국어 검색의 미확정 범위를 구별한다. 현재 근거가 없는 배포 완료/검색 해결을 추가하지 않는다.
- `src/content/blog/{ko,en}/ollama-to-vllm.md`: 테스트/운영 장비와 양자화 포맷 차이, 지표 정의를 구별한다. 출처가 불명확한 외부 엔진 순위표를 걷어내고 비교가 성립하는 범위를 적는다. 실행 명령의 줄 연결을 고친다.
- `src/content/blog/ko/vllm-kv-cache-admission.md`: 측정 집단과 코퍼스의 한계, 실제 시험/검토의 구분, 채택 기준을 명시한다. 전력만으로 연산 병목을 배제하거나 튜닝 후보 기각을 모든 엔진 개선의 부재로 확장하지 않는다.
- 검증: 증거가 없는 성공담, 새로운 내부 수치, 조건을 넘는 일반화가 추가되지 않았는지 독립 검토.

### T3. 사용자별 LLM 백엔드 격리 글

- 새 파일: `src/content/blog/{ko,en}/per-user-llm-backend.md`.
- 개인 설정 실패 시 공용 경로로 자동 전환하던 문제, 선택 범위/비용 귀속, 호출 경로 배선, 오류 회복, 확인한 테스트 범위 중심으로 작성한다.
- 개인용 설정 값과 키를 노출하지 않는 가상 예제, 비공개 시스템과 다른 이름을 쓴다. 새 설명 예제는 실제 구현 재현이라고 주장하지 않는다.
- 자동 갱신의 모든 실계정 경로 검증이나 전체 환경 검증을 주장하지 않는다. 원천의 로컬 검증 범위를 유지한다.
- 독자가 볼 수 있는 완성된 글로 준비하되 배포는 수행하지 않는다.

### T4. 대표글 안내

- `src/content.config.ts:7`: 선택적 양의 정수 `featuredOrder` 필드 추가.
- `src/pages/[lang]/index.astro:16`: 대표글을 translationKey별로 선택한다. 현재 언어 번역이 있으면 그 글을, 없으면 실제 언어를 표시한 원문을 연결한다. 초안은 항상 제외한다.
- `src/i18n.ts`, 필요 시 `src/styles/global.css`: 대표글/전체 글 라벨, 다른 언어 표시와 좁은 화면 배치.
- 대표 순서: 신규 사용자 격리, 단일 서버 배포, 서빙 전환, 서빙 부하 검증. 기존 주소와 언어 기본값, 전체 글의 날짜 정렬은 보존한다.
- Given 한영 번역 쌍과 한국어 단독 글 / When 두 홈을 렌더 / Then 대표글은 중복 없이 4개이고 실제 존재하는 언어 경로로 이동한다.
- Given draft 글 / When 홈, RSS, 글 경로를 생성 / Then 초안은 노출되지 않는다.

### T5. 검증과 인계

- `npm ci --cache /private/tmp/blog-career-npm-cache`, `ASTRO_TELEMETRY_DISABLED=1 npm run build`, `git diff --check`.
- 새 설명 코드의 실행 가능성을 확인한다. 동작을 약속하는 예제에 한해 성공/실패/격리 경계를 실제로 실행한다. 단순 문장 수정용 형식 테스트는 추가하지 않는다.
- 생성 HTML에서 글 수/한영 링크/대표글 순서/내부 링크/날짜를 확인한다. 초안 제외는 기존 필터와 대표 필터를 함께 확인한다.
- 로컬 브라우저에서 양쪽 홈, 대표글, 모바일 폭, 표/다이어그램 렌더를 확인한다.
- 독립 리뷰 후 문제를 반영한다. `docs/CAREER_BLOG_REFRESH_RESULT.md`에 바뀐 것, 검증, 근거 한계와 후속 후보를 기록한다. 커리어 원천 문서를 공개 저장소로 복사하지 않는다.
- 작업 브랜치에 커밋하고 non-force push 및 draft PR을 만든다. main 병합과 배포는 하지 않는다.

## 의존 관계와 병렬 작업

T1 근거 확보 → 계획 독립 검토 → T1 정정/T2 대표 보강/T3 신작(파일 소유권 분리, 병렬) → T4 통합 → T5 검증/리뷰/인계.

예상 변경 상한: 기존 콘텐츠 23개 내 부분 수정, 새 콘텐츠 2개, UI/스키마 4개 내, 계획/결과 문서 2개, 필요한 재현 예제. 전체 글 개작과 별도 플랫폼 구축은 하지 않는다.

## 위험과 멈춤 조건

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 과거 작업의 빈 결말을 추측 | 사실 신뢰도 손상 | 확인 범위만 서술, 미확인 결과 명시 |
| 커리어 자료의 비공개 정보 유출 | 공개 범위 위반 | 새 내부 수치/식별자 제외, 가상 예제와 일반화된 표현 |
| 한영 기술 내용 불일치 | 독자가 다른 주장 접함 | 같은 translationKey의 수정 대조 |
| 대표글의 존재하지 않는 언어 링크 | 읽기 실패 | 실제 entry의 언어로 링크, 빌드/브라우저 점검 |
| 기존 작업 변경 또는 충돌 | 사용자 작업 손상 | 시작 시 clean 확인, 충돌/관련 변경 발견 시 중단 |
| 원인 불명 빌드 실패 또는 검증 불가 | 완료 판단 불가 | 범위 외 변경 없이 원인 조사 후 보고 |
| diff가 위 범위를 초과 | 승인 범위 이탈 | 진행 전에 보고하고 범위 조정 |

## 노력 점검

핵심은 사실 정정, 대표글과 새로운 실행 경계 사례다. 사이트 기능은 대표 목록만 추가하고 새 프레임워크나 디자인 시스템을 만들지 않는다. 계획/검증/인계 비용을 포함한 총노력은 핵심 작업의 약 1.5배로 예상한다.

## 독립 계획 리뷰

상태: LGTM. 독립 에이전트가 사용자 합의, 공개 범위, 번역, 언어 fallback, 검증 범위를 검토했고 차단 사항은 없었다.

실행 시 보강: 과거 사건은 해당 시점 기록과 대조하며 최신 별개 경험을 소급하지 않는다. 결과 문서에도 비공개 식별자를 옮기지 않는다. 번역 쌍의 featuredOrder는 동일하게 유지한다.
