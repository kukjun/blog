# 블로그 보강 결과

2026-09-13 | [이슈 #1](https://github.com/kukjun/blog/issues/1) | `docs/1/career-blog-refresh`

기존 한국어 18편과 영어 번역 5편을 정정하고, 사용자별 LLM 백엔드 격리 글을 한영으로 추가했다. 현재 한국어 19편, 영어 6편이다. [계획](./CAREER_BLOG_REFRESH_PLAN.md)의 범위 안에서 작업했다.

## 무엇을 보여주는 블로그인가

에이전트가 어떤 설정과 권한으로 실행되는지, 배포 환경이 바뀌면 어떤 책임이 남는지, 서빙 전환을 어떤 근거로 판단했는지를 먼저 보여준다. 홈 소개와 검색용 설명도 이 주제로 구체화했다.

대표 순서는 아래와 같다. 영어 홈에서는 번역이 있는 글을 선택하고, 한국어만 있는 두 글은 언어를 표시해 원문으로 연결한다.

1. [사용자별 LLM 백엔드](../src/content/blog/ko/per-user-llm-backend.md): 선택 범위, 비용 귀속, 호출 경로, 실패 후 회복. 새 글과 실행 가능한 가상 예제를 추가했다.
2. [단일 서버 배포](../src/content/blog/ko/k8s-to-single-box.md): 제거하는 구성과 남는 운영 책임, 인증서 조치, 한국어 검색의 미확정 범위를 구별했다.
3. [Ollama에서 vLLM으로](../src/content/blog/ko/ollama-to-vllm.md): 장비와 양자화 조건, 기록된 처리량, 정성 출력 비교, 게이트웨이 전환 판단을 나누었다.
4. [KV 캐시 부하 검증](../src/content/blog/ko/vllm-kv-cache-admission.md): 재생 코퍼스의 한계, 운영 관측과 시험의 차이, 후보를 채택하지 않은 판단을 보강했다.

## 글별 처리

장애 조사와 실패한 시도도 판단 과정을 보여줄 수 있어 글 자체를 삭제하지 않았다. 근거가 없는 문장과 불일치하는 표를 걷어냈다. 기존 주소, 발행일, 번역 연결 키는 보존했고 수정일을 표시했다.

| 주제 | 처리와 이유 |
| --- | --- |
| 사용자별 LLM 백엔드 | 신작. 개인 설정 실패를 공용 경로로 넘기지 않는 경계와 실제 검증 범위 설명 |
| 단일 서버 배포 | 대표글 보강. 검색 해결과 고객 배포 완료는 주장하지 않음 |
| Ollama → vLLM | 대표글 보강. 불일치 지연 표와 비교 조건이 다른 엔진 순위표 제거 |
| KV 캐시 | 대표글 보강. 9개 검토, 5개 직접 시험, 채택 0을 구별 |
| 에이전트 메모리 | 미완성 조사로 유지. 초기 적재 표본의 조회 편향을 전체 회상 동작으로 일반화하지 않음 |
| LangGraph/Pregel | 상태 충돌, pending writes, 재개, 외부 부작용을 실행 예제로 확인 |
| 세션 라우팅 | 당시 작업 단위의 경로 고정으로 한정. 원격 브라우저 연결의 일반적 불가능 주장 제거 |
| Redis 락 | 트랜잭션 격리와 DB 제약 대안 설명. TTL 만료 뒤 기존 작업이 계속될 수 있음을 명시 |
| 열린 트랜잭션 | 당시 커넥션 반환 경로의 문제로 한정. commit/rollback 실패 처리의 한계 표시 |
| 프롬프트 캐시 비용 | 적중률만으로 비용을 단정하지 않음. 예상 절감과 관측한 청구를 구별 |
| NFS OPEN 증폭 | 구간 커널 카운터와 파일 호출 수 구별. 맞지 않는 배수 검산과 리플리카 일반화 제거 |
| EFS 용량 해석 | 런타임의 당시 숫자 변환 문제와 가디언 입력 검증 책임 설명 |
| EFS 정리 정책 | 비율 단위를 맞추고 검증 계획을 실행 완료처럼 읽히지 않게 정정 |
| S3/PVC/EFS | SQLite와 네트워크 파일시스템, access point의 제약 보정. 비교 조건 불명확한 개선 수치 제거 |
| EKS IP 버퍼 | 짧은 관측의 개선과 이후 잔여 실패 구별. 절대 하한 검토를 완전 해결로 표현하지 않음 |
| 레거시 미사용 조사 | 참조 유무의 모순 제거. 접근 로그의 누락 가능성과 쓰기 주체 미확정 범위 명시 |
| 컷오버 | 재시도 횟수 산술 보정. 생산자 전환과 소비자 전환, 종료 판단과 실제 종료 결과 구별 |
| 측정 근거 없는 숫자 | 검색 실패를 숫자의 비존재 증명으로 쓰지 않음. 수용량 추정, 배수, 관측 동시성의 단위 구별 |
| Ollama 외부 사용 | 외부 요청과 커널 경고는 관측으로, 유입 경로와 hang의 인과는 가설로 구별 |

영어 번역이 있던 5개 주제에는 같은 기술 정정을 반영했다. 새 백엔드 글의 한영 코드도 일치한다.

## 검증

| 항목 | 결과 |
| --- | --- |
| 고정 의존성 설치 | `npm ci --cache /private/tmp/blog-career-npm-cache` 통과. lockfile 변경 없음 |
| 정적 빌드 | `ASTRO_TELEMETRY_DISABLED=1 npm run build` 통과 |
| 콘텐츠 캐시 | 편집 중 발생한 중복 ID 경고는 `ASTRO_TELEMETRY_DISABLED=1 npm run astro -- sync --force` 후 빌드에서 재발하지 않음 |
| 메타데이터 | 기존 23개 파일의 pubDate, translationKey, lang, draft 보존과 수정일 확인 |
| 생성 결과 | 글 경로와 RSS 각각 한국어 19개, 영어 6개. 전체 목록 날짜 내림차순 확인 |
| 대표 목록 | 언어별 4개, 번역 중복 없음. 영어 홈의 한국어 원문 연결 2개 확인 |
| 링크 | 생성 HTML의 내부 링크 대상과 내부 앵커 확인 |
| 초안 필터 | 홈, 글 경로, RSS의 draft 제외 코드 확인. 임시 초안을 추가한 통합 시험은 수행하지 않음 |
| 백엔드 예제 | `node public/examples/backend-scope.mjs` 통과. 미등록, 무효 설정, 모의 429, 사용자 격리, 설정 복구, 명시적 공용 선택 검사 |
| LangGraph 예제 | `uv run --no-project public/examples/langgraph-supersteps.py` 통과. 충돌, pending writes, 같은 실행 재개, 남는 외부 부작용 확인 |
| 서빙 명령 | 셸 문법과 인자 전달 검사 통과. GPU 서버 실행은 하지 않음 |
| 화면 | 한영 홈, 대표글, 번역 이동, 390px 모바일 폭, 표와 Mermaid 렌더 확인 |
| 변경 형식 | `git diff --check` 통과 |

독립 리뷰에서 발견한 영문 주석의 과도한 보장, 세션 라우팅과 캐시의 일반화, 메모리 조회 표본의 범위, 숫자의 단위 모순, S3 로그의 완전성 주장도 수정했다.

의존성 설치 시 기존 잠금 버전에 대한 npm 취약점 경고가 있었다. 이 작업은 패키지 업데이트나 보안 점검을 포함하지 않으며 해당 경고를 해소했다고 주장하지 않는다.

## 검증의 한계와 다음 글의 재료

과거 운영 실험을 다시 실행한 작업은 아니다. 기존 공개 수치와 현재 남은 기록을 대조했고, 출처가 불충분한 값은 제거하거나 해석 범위를 좁혔다. 새로운 내부 수치와 비공개 운영 코드는 싣지 않았다. 두 실행 예제는 설명을 위해 새로 썼으며 실제 제품 구현이나 전체 운영 보장을 대신하지 않는다.

다음 보강은 더 큰 성공 수치를 쓰는 것보다 실제 종료 조건을 확인하는 데서 시작하면 된다.

- NFS 반복 조회 수정 전후를 같은 요청, 캐시 조건, 응답 시간과 카운터로 비교한 기록
- 단일 서버 형상에서 한국어 검색의 실제 쿼리와 최종 검증, 백업과 재시작 결과
- EKS 버퍼 변경 후 여러 배치 주기와 노드 교체 구간을 포함한 관측

각 항목은 후속 자료가 확보되면 쓸 수 있는 후보이며, 이번에 완료한 성과가 아니다. 작업은 검토용 브랜치와 draft PR으로 인계하고, main 병합과 배포는 별도로 다룬다.
